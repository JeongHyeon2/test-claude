# FrameSpeed — 웹

블랙박스 영상 속도 분석 **업무 화면**입니다. 홍보 페이지가 아니라, 사건을 열어 놓고
숫자를 읽고 인용하는 도구로 만들었습니다. React + Vite, 속도 그래프는 Recharts 입니다.
운영 Supabase 를 **읽기 전용**으로 봅니다.

## 실행

```bash
npm install
npm run dev                        # 개발 서버
npm run build && npm run preview   # 빌드 결과 확인 (8899)
```

`.env` 에 두 값이 필요합니다.

```
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

여기 들어가는 키는 **anon 키뿐**입니다. 브라우저에 실리는 게 정상이고, 방어선은 키가 아니라
DB 의 RLS 와 GRANT 입니다. 이 키로 할 수 있는 일은 공개 샘플 읽기와 조회 함수
`get_result_by_token` 이 전부입니다. `service_role` 키는 어떤 경우에도 이 폴더에 두지 않습니다.

## 화면

| 경로 | 화면 | 하는 일 |
|---|---|---|
| `#/` | 사건 목록 | 조회 번호로 사건을 불러오고, 불러온 사건을 표로 훑습니다 |
| `#/case/{조회번호}` | 사건 상세 | 판정 · 속도 그래프 · 구간 · 근거 프레임 · 사건 정보 |
| `#/new` | 새 분석 접수 | 영상 1차 검사(확장자 · 용량 · 길이 · 해상도 · SHA-256) |

해시 라우팅이라 정적 호스팅에서 새로고침해도 404 가 나지 않습니다.
확인용 조회 번호 — `smpl_9f3a71c0be48d2115c7e0a9f4d83b672`

## 사건 목록이 로컬에 남는 이유

브라우저에 실린 키로는 `jobs` 표를 통째로 읽을 수 없습니다(RLS). 그래서 조회 번호로
불러온 사건만 `localStorage` 에 쌓아 목록으로 보여줍니다 — 실무에서 최근 작업 목록을
들고 있는 것과 같은 모양입니다. 사건 내용은 저장하지 않고 표에 쓸 몇 줄만 둡니다
(`src/store.js`). 계정별 사건 목록은 서버에서 내려줘야 합니다.

## 속도 그래프

`src/components/SpeedChart.jsx` 하나에 모여 있습니다.

- 파란 선이 추정 속도, 주변 옅은 띠가 오차 범위(±5km/h)
- 감속 구간은 배경에 옅게 깔아, 마우스를 올리기 전에도 브레이크 시점이 먼저 보입니다
- 세로 실선이 충돌 추정 시각, 빨간 점선이 최대 감속 시각
- **마우스를 올리면** 그 시점의 속도 · 추정 범위 · 가감속(km/h·s) · 오차 ·
  속한 구간(가속/정속/감속)과 그 구간의 시간·속도 변화가 함께 나옵니다
- `compact` 를 주면 참조선 라벨을 접고 툴팁을 줄입니다

## 인용할 때 화면이 챙기는 것

- 속도를 한 값이 아니라 **구간**으로 인용하도록 상세 화면에서 안내합니다
- **영상 해시(SHA-256)** 를 전문 그대로 보여주고 복사 버튼을 답니다 — 분석한 영상이
  제출 영상과 같은 파일인지 확인하는 근거입니다
- **보관 만료일**을 남은 일수와 함께 띄우고, 지난 건은 화면 맨 위에서 먼저 알립니다

## 아직 서버가 필요한 것

이 앱은 DB 를 **읽기만** 합니다. 실제 접수(`POST /api/jobs`) · PDF 생성 ·
전문가 검토 신청 · 정확도 피드백 · 메일 재발송은 모두 쓰기라 서버가 있어야 합니다
(`framespeed/apps/web/app/api/*`). 근거 프레임 이미지도 비공개 저장소에 있어
서버가 발급한 링크로만 열립니다.

해당 버튼(전문가 검토 신청 · 프레임 이미지 · 접수)은 화면에서 잠긴 상태로 둡니다. 예전에는 화면마다 "이 환경에서 동작하지 않는 것" 안내를 접어 두었는데, 실무자가
볼 화면에 우리 사정이 끼어들면 제품이 아니라 데모처럼 읽혀서 걷어냈습니다. 그 내용은
개발자가 읽을 이 문서에만 둡니다.

## PDF 저장 · 인쇄

`PDF 저장 · 인쇄` 버튼은 `window.print()` 를 부릅니다. 브라우저 인쇄 대화상자에서
"PDF로 저장"을 고르면 그대로 PDF 가 나옵니다 — 그래프도 래스터가 아니라 벡터로 들어갑니다.
서버 없이 동작하므로 이 앱에서 유일하게 끝까지 되는 산출물입니다.

인쇄 규칙은 `src/styles.css` 의 `@media print` 한 덩어리에 모여 있습니다.

- 좌측 메뉴 · 상단 버튼 · 검색창처럼 종이에 있을 이유가 없는 것은 `.print-hide` 로 걷어냅니다
- 반대로 화면에선 군더더기인 머리말(파일명 · 조회 번호 · 영상 해시 · 분석 일시 · 보관 만료)은
  `.print-head` 로 종이에만 넣습니다 — 출력물만 돌아다녀도 어느 영상의 어느 분석인지 남아야 합니다
- `사건 정보` 패널은 머리말과 겹치므로 인쇄에서 뺍니다. `인용 시 확인`(고지 문안)은 반드시 남깁니다
- "그래프에 마우스를 올리면…" 같은 화면 전용 안내도 뺍니다
- `print-color-adjust: exact` — 이게 없으면 감속 구간 띠와 고지 문안 바탕색이 날아가
  회색 덩어리가 됩니다
- `break-inside: avoid` — 패널이 페이지 경계에서 갈라지면 표 머리와 몸통이 따로 놉니다

A4 세로 기준 2쪽으로 떨어집니다.

## 엑셀 저장

`엑셀 저장` 버튼은 브라우저에서 `.xlsx` 를 만들어 내려줍니다. 시트 4장입니다.

| 시트 | 내용 |
| --- | --- |
| 요약 | 파일명 · 조회 번호 · 영상 해시 · 분석 일시 · 모델 · 보관 만료 · 판정 수치 · 고지 문안 |
| 시계열 | 표본마다 시각 · 속도 · 하한 · 상한 · 가감속 · 속한 구간 |
| 구간 | 순번 · 구분 · 시작 · 종료 · 지속 · 속도 변화 · 변화율 |
| 근거 프레임 | 번호 · 영상 시각 · 그 시점 속도 · 가감속 · 구간 · 속도 산출 방식 |

- 근거 프레임 시각이 시계열 표본과 어긋나면 앞뒤 표본을 **선형 보간**하고,
  마지막 열에 `표본값` / `앞뒤 표본 선형 보간` 중 무엇인지 적습니다 —
  받는 쪽이 그 숫자를 어디까지 믿어야 하는지 알아야 합니다.
- 셀에 담기는 값은 소수 3자리로 반올림합니다. `8.8 - 6` 이 `2.8000000000000007` 이
  되는데, 서식이 표시만 가려 줄 뿐 값 자체가 지저분하면 받는 쪽에서 다시 계산할 때
  그대로 따라갑니다.
- 시트를 만드는 `buildBook()` 은 브라우저 API 를 쓰지 않는 순수 함수라
  Node 에서 그대로 불러 결과 파일을 검증할 수 있습니다 (`src/lib/excel.js`).
- `write-excel-file` 은 버튼을 누를 때 동적으로 불러옵니다. 첫 화면에 71KB 를
  얹을 이유가 없습니다.
